Reported index and commodity movements
=====================================

This focused news-only correction recognizes a named market index or commodity
as the headline subject of a reported movement. The same narrow predicate feeds
both existing hooks: market classification and factual-title sufficiency. It
does not promote every mention of an index, a commodity word or a price forecast.
Corporate names, corporate actions, speculation and promotional material do not
become factual market evidence through this new rule.

The original headline is retained unchanged. No price, percentage, cause or
missing source context is invented. Recognition supplies eligibility for the
existing checks, not a publication decision: attributed source metadata, rights,
freshness, evidence limits, canonical AI analysis, independent quality review,
related/relevance requirements, routing and send-time validation still apply.
An accepted analysis is not proof that an underlying report is true or useful.

No provider, model, budget, retry allowance, quality threshold, trading strategy,
order, position, accounting, schema or backup format changes are included.
The separate findings about local-crime market usefulness and SEC extraction
diagnostics are not implemented here. No historical replay or requeue occurs.

Verification and release
------------------------

Isolated fixtures reproduce the Nasdaq-classification and gold-sufficiency gaps,
then cover reported movements and corporate/opinion/forecast negative controls.
Pipeline tests retain original evidence and existing gates. PostgreSQL tests
exercise the normal durable analysis/outbox and restart/deduplication path with
mocked completions only; a pending outbox row is not actual Telegram delivery.
No real provider fetch, inference, test message or trade is required.

Release uses the existing exact-commit CI/Readiness, encrypted predeployment
backup and all-role readiness gates. It needs no migration or new runtime flag.
The actual previously running server image is the return target, on the current
database without rewinding data. Stored evidence and public analysis contracts
are unchanged; returning to the old binary can lose the new recognition, not
grant permission to reinterpret or replay historical terminal events.

Observe naturally new eligible events after release. Distinguish unique events,
versions, analysis jobs, repair requests and actual public messages. Tests do not
establish a volume increase, semantic accuracy, trading edge or profitability.
